# Http2postman

Convert JetBrains HTTP Client (`.http`) and VS Code REST Client (`.rest`) requests into a
**Postman Collection v2.1** JSON file — from the IDE, the command line, or your own code.

> [!WARNING]
> **Beta version — not fully tested.**
> This plugin is still in beta and has not undergone complete testing. Bugs, edge-case failures and
> unexpected output are possible. Please review the generated collection and keep backups of your
> request files before relying on it. Bug reports are welcome.
>
> **AI-generated code.** The code in this repository was generated with a language model and has
> only been partially tested. Obvious bugs found during review were fixed, but paths that were never
> exercised may still misbehave. Treat the output as a starting point, not as a guaranteed
> conversion.
>
> **Ported from a Python project.** The `.http` parsing and collection-building logic is a Java
> port of [salitaba/http2postman](https://github.com/salitaba/http2postman) (MIT), so the behaviour
> — including its quirks and unsupported constructs — largely mirrors the upstream implementation.

## Project status and provenance

This plugin exists to scratch a specific itch: JetBrains IDEs can run `.http` files but cannot export
them, and Postman cannot import them. The implementation was generated by a language model, then
partially tested and patched by hand: obvious bugs found along the way were fixed, but untested paths
were left as they are. Testing so far covers the converter fixtures in
`javacli/src/test` (methods, URLs, headers, bodies, variables, folders, scripts, environments,
dotenv, multipart, WebSocket/gRPC reporting). Real-world `.http` corpora have not been run, so
please report anything that converts incorrectly.

The parser and converter are a line-by-line Java translation of the Python implementation in
[salitaba/http2postman](https://github.com/salitaba/http2postman). Upstream's MIT license and
attribution are kept in [`javacli/LICENSE`](javacli/LICENSE) and
[`javacli/THIRD_PARTY_NOTICES.md`](javacli/THIRD_PARTY_NOTICES.md). Improvements and bug fixes made
here are not upstreamed automatically; the two implementations may drift.

## Features

- **IDE integration** — right-click one or more `.http`/`.rest` files, or a whole folder, and run
  *Convert to Postman Format File*. Conversion runs in the background and reports the result in a
  notification.
- **Postman Collection v2.1** — requests, folders, variables, auth, bodies and scripts.
- **Folders** — a directory is scanned recursively; files of a folder become one collection.
- **JetBrains environments** — values from `http-client.env.json` / `http-client.private.env.json`
  become collection variable defaults.
- **dotenv** — `{{$dotenv VAR}}` resolves from the `.env` next to each source (or an explicit file).
- **Dynamic variables** — JetBrains `$uuid`, `$random.email`, ... map to their Postman equivalents.
- **Scripts** — `< {% ... %}` / `> {% ... %}` blocks become Postman Pre-request / Tests scripts.
- **Honest reporting** — anything Postman cannot express (WebSocket, gRPC, unmapped dynamic
  variables, unresolved dotenv references) is reported with a `file:line` reference instead of being
  silently dropped.
- **Safe** — source files are never modified and output is written atomically.

## Requirements

- An IntelliJ Platform IDE with the JSON module (`com.intellij.modules.json`); the plugin is built
  against IntelliJ IDEA `2025.3.6.1`. Other IDEs (WebStorm, PyCharm, ...) are untested.
- Java 17 to run the CLI and to build the project.

## Installation

From JetBrains Marketplace: **Settings | Plugins | Marketplace**, search for *Http2postman*, and
install it. Beta builds may be published to the Marketplace *Beta* channel, which has to be enabled
explicitly before the update is offered.

From a local build: **Settings | Plugins | ⚙ | Install Plugin from Disk...** and pick
`build/distributions/http2postman-<version>.zip` (see [Building](#building)).

## Usage in the IDE

1. Right-click `.http`/`.rest` files or a folder in the Project view (or an open editor tab) and
   choose **Convert to Postman Format File**.
2. Adjust the options and press **Convert**:

| Option           | Description                                                                 | Default                   |
|------------------|-----------------------------------------------------------------------------|---------------------------|
| Output directory | Where the collection is written.                                            | Project root              |
| File name        | Name of the generated JSON file.                                            | `postman_collection.json` |
| Collection name  | Name shown in Postman.                                                      | Title-cased first source  |
| Environment      | Values from `http-client.env.json` become collection variable defaults.     | `None`                    |
| `.env` file      | File used for `{{$dotenv VAR}}`; empty means `.env` next to each source.    | Auto-detected             |
| Open after       | Open the generated collection in the editor when conversion finishes.       | On                        |

3. A notification reports `requests, folders, variables, scripts`; warnings about constructs that
   cannot be expressed in Postman are shown separately. An existing output file asks for
   confirmation before being overwritten.
4. Import the file into Postman: **Import | Files**.

## Command line

The converter lives in the standalone [`javacli`](javacli) module (Maven, Java 17). It is the same
code the plugin runs in-process.

Build and run it with Maven (Jackson is on the runtime classpath through Maven):

```sh
cd javacli
mvn -q compile exec:java -Dexec.mainClass=com.auhouhs.http2postman.cli.Main \
    -Dexec.args="requests.http -o collection.json"
```

```
usage: http2postman [-h] [-o OUTPUT] [--quiet] [--name NAME]
                    [--env-file PATH] [--prefer-env NAME]
                    PATH [PATH ...]
```

| Flag                  | Description                                                                     |
|-----------------------|---------------------------------------------------------------------------------|
| `PATH ...`            | `.http`/`.rest` files and/or directories (scanned recursively).                 |
| `-o, --output PATH`   | Output JSON file. Defaults to `postman_collection.json` next to a single input file, or in the working directory. |
| `--name NAME`         | Collection name. Defaults to the first source file's name.                      |
| `--env-file PATH`     | `.env` file for `{{$dotenv VAR}}`; defaults to `.env` next to each input.       |
| `--prefer-env NAME`   | Use environment `NAME` from `http-client.env.json` as collection variable defaults; a missing file or name is an error. |
| `--quiet`             | Suppress the stdout report.                                                     |
| `-h, --help`          | Print usage.                                                                    |

Exit codes: `0` success, `1` conversion/validation failure, `2` usage error.

When the generated JSON would exceed 2 MB and more than one source file was given, the CLI writes
one collection per source instead (`<output-stem>-<source>.json`).

## Programmatic API

The plugin calls `PostmanConversion`, which mirrors the CLI options and throws
`ConversionException` on failure:

```java
import com.auhouhs.http2postman.api.ConversionRequest;
import com.auhouhs.http2postman.api.ConversionResult;
import com.auhouhs.http2postman.api.PostmanConversion;
import java.nio.file.Path;
import java.util.List;

ConversionResult result = PostmanConversion.convert(new ConversionRequest(
        List.of(Path.of("requests.http")),
        Path.of("out/postman_collection.json"),
        "My API",            // collection name, null derives it from the source
        null,                // .env file, null auto-detects
        null                 // environment name, null disables it
));

System.out.println(result.requests() + " requests, " + result.warnings().size() + " warnings");
```

## What is converted

- `###` request names, `# @name` overrides, all HTTP methods (unknown methods pass through)
- headers (order and casing preserved; `Content-Length` dropped)
- raw / JSON / XML / urlencoded / multipart / external-file bodies
- GraphQL requests via `X-REQUEST-TYPE: GraphQL`
- file-level `@name = value` variables and `{{var}}` tokens
- `## Folder` / `@group` grouping
- JetBrains response handlers and pre-request scripts
- `Bearer`, `Basic` and OAuth2 client-credentials token requests as Postman auth objects

## Limitations

- **WebSocket** (`WEBSOCKET ws://...`) and **gRPC** (`GRPC host/service/method`) blocks are parsed
  but not converted — they are reported under *Unsupported* with a `file:line` reference.
- JetBrains **response-file redirects** are reported, not converted.
- Script translation covers common `client.*` / `response.*` calls; unrecognized statements are
  passed through unchanged and may need manual review.
- Unmapped `$random.*` variables and unresolved `{{$dotenv VAR}}` references are kept as-is and
  reported.
- Behaviour tracks the upstream Python implementation, including cases where Postman's model cannot
  represent a JetBrains feature exactly.

## Building

The plugin is built with Gradle (Kotlin DSL) and the IntelliJ Platform Gradle Plugin
(use `gradlew.bat` instead of `./gradlew` on Windows):

```sh
./gradlew runIde        # launch a sandbox IDE with the plugin installed
./gradlew buildPlugin   # build build/distributions/http2postman-<version>.zip
./gradlew verifyPlugin  # check compatibility against the target IDEs
```

The converter tests live in the Maven module:

```sh
cd javacli
mvn test
```

## Contributing

Issues and pull requests are welcome, especially conversion edge cases from real-world `.http`
files. If the generated collection does not import into Postman, please attach a redacted sample
file and the warning notification text. Because the parser is a port of the Python project, please
mention whether the same input converts correctly with upstream
[salitaba/http2postman](https://github.com/salitaba/http2postman) — that makes triage much easier.
